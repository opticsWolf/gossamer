# Code review — 2026-09-09 (CodeRadar, post-0.9.2)

Scope: full `gossamer` tree at `dev_rust@5fda0b4` (158 files, 480
classes, 3340 functions, 6470 call edges), first review since the
0.9.1/0.9.2 refactors (`src/adapters/` + `fetch.rs`/`bridge.rs`
splits, version-gated error spellings, CI fixes). Methods: `smells`
(normal), `dead_code` (conf ≥ 0.75), `scaffolding`; `clones` timed
out twice on the full graph (noted, not run — see §4).

## Verdict

No new debt from the refactor window, nothing to fix. The three
finding classes reduce to: false positives (dead code), by-design
stubs/notes (scaffolding), and pre-existing parity-pinned complexity
(same hotspots as the 2026-09-05 review, now at their new paths).
One review pass with one dismissal is recorded in §5.

## 1. Dead code (~2658 findings): all false positives

Three systematic blind spots, verified class-wide including the full
top-60 "most deletable" list (every entry is public API):

- pytest entry points — every `test_*` is "unreachable".
- The PyO3 boundary — every `#[pyfunction]` (`ssrf_check_url`,
  `*_parse_search/fetch`, …) and `BibliographicRecord.new`/`_core`
  are "unreachable".
- Dynamic dispatch — toolbox/adapter/service methods reached via
  `TOOL_REGISTRY`, MCP, CLI, or `execute_tool` (`Crawler.crawl`,
  `FetchService.batch_inspect_pages_impl`, `Cache.get`,
  `ToolboxConfig.from_dict`, all `Adapter._search_impl`/`fetch`, …).

Spot-checks (`_browser_provenance`, `parse_headers`, `inject_auth`,
`extract_links_from_html`, `count_tokens`) are all live via dispatch
or the bridge. **Do not act on dead-code findings without
`triage via affected()` — and in this repo, assume guilty-until-proven
(the graph cannot see pytest, PyO3, or string dispatch).**

## 2. Scaffolding (60 findings): nothing real

- 30 placeholder bodies: `.pyi` stub bodies (that is what a stub file
  is), `log_message: pass` test doubles, `Guard.scan`/`stats`
  Protocol `...` bodies. All by design.
- 30 comment markers: "Phase N" notes in CHANGELOG (historical
  record) and composition-phase headers in module docstrings
  (`crawl.py`, `fetch.py`, `document.py`, `research_providers.py`,
  …). Provenance, not leftover scaffolding.

## 4. Clones: not run

`find_clones` timed out twice over the full graph. Known intentional
duplication, no scan needed: vendored `_v_*` oracles in
`test_rust_parity_*.py` (byte-parity by design — must NOT be
"deduplicated" against the Rust code), per-adapter search/fetch
shapes (same contract, different endpoints), hostile-corpus fixtures
shared across adapter tests. If a future change needs it, scope the
scan to `gossamer/` excluding `tests/`.

## 5. Reviewed and dismissed

- **`shared_client` (`fetch.rs`, LOC 69/cx 11)** — read in full: one
  `get_or_init` closure doing strictly sequential builder
  configuration (timeout → UA → proxy → headers → cookies), each
  step warn-and-continue. No branching depth, runs once per
  process, pinned by `test_m9_http_pool.py` (source + behavior).
  Extracting would scatter a coherent build sequence. Dismissed.
- **New 0.9.1/0.9.2 code is clean** — zero flags on
  `dict_slice_error`, `re_sub_type_error`, `str_subscript_error`,
  `note_runtime_minor`/`runtime_minor`, the `has_scheme` gate, and
  `render_ip`. The splits moved flags with their functions; no
  function got more complex in the move.

## 6. Recommendations

None blocking. Opportunistic only: if touching `eurostat_unpack_impl`
or `doaj_row_impl` for product reasons, their parity suites make
splitting safe — but do not refactor for the metric alone.

# gossamer — Detailed Review Report

> **Date:** 2026-09-05 · **Version reviewed:** 0.5.7 (pyproject) / 0.5.3 (Cargo, see §F.1)
> **Method:** static reading of all 27 modules + `src/lib.rs`, live probing against the
> built extension (`.venv`), full test-suite run.
> **Suite health at review time:** **1206 passed, 11 skipped** (all skips are intentional:
> 10× `GOSSAMER_LIVE`-gated live tests, 1× guard-absent test) in ~21 s. No failures.
>
> This report deliberately covers only what the existing docs don't: prior audits
> (`docs/CODE_REVIEW_2026-08-27.md`, `docs/SPEC_AUDIT.md`, `docs/IMPROVEMENT_PLAN.md`)
> already disposition their own findings. Every item below was verified against the
> current tree; items I reproduced interactively say **Reproduced**. Severity scale:
> 🔴 High (wrong results, crash, resource exhaustion, security-relevant) ·
> 🟡 Medium (silent misbehavior, degraded quality, dev-setup breakage) ·
> 🔵 Low (polish, consistency, future-proofing).

**TL;DR.** The core pipeline (static fetch → cache → budget → provenance) is solid and
well-tested. The defect density is highest at the *seams*: MCP/LLM schema generation,
string-vs-list input handling, four competing URL-identity functions, parameters that
are accepted and then ignored, and the document-download path which bypasses the size
cap that the page-fetch path enforces. Nothing here requires an architecture change;
almost everything is a small, testable fix. Recommended order: §A first (all small),
then §B, then §C.

## A. Confirmed bugs (fix these first)

### A.1 🔴 `min_score: float` is advertised to LLMs/MCP as an array-of-strings schema

**File:** `gossamer/config.py` — `ToolParam.json_schema` (~line 104).

The schema builder branches on `str` / `int` / `bool` / *else → `list[str]`*.
`focused_discovery.min_score` is declared `float`, so it falls into the `else` branch:

```python
# Reproduced:
>>> spec.params['min_score'].json_schema
{'type': 'array', 'items': {'type': 'string'}, ..., 'default': 0.05}
```

Consequences: the MCP input schema and `get_llm_definitions()` tell the model that
`min_score` is an array of strings. Strict MCP clients will reject a numeric
`min_score`; lenient ones will send garbage the Python side then coerces with
`float(...)`. Any future `float` param inherits the same bug.

**Fix:** add an explicit `float` branch (`{"type": "number"}`), and add a registry test
asserting every `ToolParam.type` maps to the expected JSON-Schema type (the existing
P8 registry tests check shape, not type mapping — that's why this slipped through).

### A.2 🔴 `extract_document` URL downloads bypass the S3 size cap (unbounded `response.content`)

**File:** `gossamer/document.py` — `_fetch_document_url` (~line 340).

```python
with httpx.Client(timeout=30, follow_redirects=True) as client:
    response = client.get(url, headers=self._tb._next_headers())
    response.raise_for_status()
...
return response.content, prov   # ← whole body into RAM, no cap
```

The Rust page-fetch path enforces `max_response_bytes` twice (Content-Length
early-reject + streaming chunk cap, `src/lib.rs`). The document path enforces it
**zero times**: `response.content` materialises the entire body, and
`Path(source).read_bytes()` does the same for local files (`_extract_local`, ~line 583).
An LLM-supplied URL pointing at a multi-GB file (or a slow-drip response, since the
30 s timeout is per-operation-idle, not total) exhausts process memory. This is the
same threat class S3 was created for, on the higher-bandwidth path (binaries are
bigger than pages).

**Fix:** stream with a byte cap (`httpx.stream` + running total, honouring
`config.max_response_bytes`), mirroring the Rust logic; add a local-file `stat()`
pre-check with the same cap and an actionable error. Tests: fake transport serving
`Content-Length: 1GB` and chunk-drip bodies.

### A.3 🟡 `check_sources` and `batch_inspect_pages` iterate a bare string character-by-character

**Files:** `agent_tools.py` — `check_sources` (`for u in urls or []`);
`fetch.py` — `batch_inspect_pages_impl` (`for raw in urls`).

```python
# Reproduced:
>>> tb.check_sources("notalist")   # a str, not a list[str]
# → 8 probes for "n", "o", "t", "a", "l", "i", "s", "t", each "blocked"
>>> tb.batch_inspect_pages("https://example.com")
# → per-character "URL rejected" entries for "h", "t", "t", "p", ...
```

A bare string is the single most likely LLM shape mistake for a `list[str]` param,
and both tools turn it into confident-looking garbage instead of one clear error.
`export_citations` has the same shape flaw (`for item in (results or [])` iterates
chars; each char fails `json.loads` and is appended as a "record" — it degrades to a
"no citable records" error rather than crashing, but the diagnostics point nowhere).

**Fix:** one shared guard, e.g. in `ToolSpec.kwargs` or a `_ensure_str_list()` helper:
`isinstance(x, str)` → either wrap (`[x]`, friendly) or return a JSON error naming the
expected type. Apply to all three tools + `focused_discovery(seed_urls=...)` (which
already wraps a bare str — make that the standard behavior everywhere).

### A.4 🟡 `batch_inspect_pages(None)` raises `TypeError` out of the tool

**File:** `fetch.py` — `batch_inspect_pages_impl`. The `for raw in urls` partition loop
runs *before* the `try:` block, so `None` (or any non-iterable) escapes as an
exception, violating the "tools return JSON errors, never raise" contract every other
tool honors. **Reproduced** (`TypeError: 'NoneType' object is not iterable`).

**Fix:** move the partition loop inside the `try`, or validate up front and return
`{"error": ...}`.

### A.5 🟡 `ToolSpec.kwargs()` shares one mutable `[]` default across calls

**File:** `config.py` — `kwargs()` (~line 141); **reproduced**:

```python
>>> k1 = spec.kwargs({}); k2 = spec.kwargs({})
>>> k1["seed_urls"] is k2["seed_urls"]
True
>>> k1["seed_urls"].append("X")  # leaks into k2
```

Today `crawl()` copies the list (`[str(s) for s in ...]`), so nothing corrupts *yet* —
but `execute_tool` and the MCP wrapper both funnel through `kwargs()`, and any future
`.append()` on the received list becomes cross-call, cross-thread state corruption.
Classic aliasing landmine.

**Fix:** `copy.deepcopy` (or at minimum `list(...)`) mutable defaults in `kwargs()`.

### A.6 🟡 Malformed `GOSSAMER_*` env vars crash MCP server startup

**File:** `gossamer/mcp_server.py` — `_env()` / `_config_from_env()`.

```python
# Reproduced:
$ GOSSAMER_MAX_TOKENS=notanint python -m gossamer.mcp_server
ValueError: invalid literal for int() with base 10: 'notanint'
```

Every numeric env var (`GOSSAMER_MAX_TOKENS`, `GOSSAMER_DDGS_DELAY`, `GOSSAMER_GUARD_THRESHOLD`,
…) propagates `ValueError` out of `get_toolbox()`, so one typo in the client config
kills the whole server with a bare traceback. The module already has the warn-and-ignore
pattern (`_env_json_dict`); numerics just don't use it.

**Fix:** wrap casts: on failure, `logger.warning(...)` and fall back to the default.
Same for `_guard_config_from_env`.

### A.7 🟡 `requirements.txt` omits `pytest-xdist`, but `pyproject.toml` mandates it

`pyproject.toml` sets `addopts = "-n auto -m 'not slow'"`. A fresh
`pip install -r requirements.txt && pytest` fails immediately with
`error: unrecognized arguments: -n` (**reproduced**). The README tells contributors to
install xdist separately (`uv pip install pytest-xdist`), but the requirements file —
the thing CI-fresh checkouts actually install — doesn't include it, and the `addopts`
makes it load-bearing rather than optional.

**Fix:** add `pytest-xdist` to `requirements.txt` (it's already the de-facto standard
path), or drop `-n auto` from `addopts` and document `-n auto` as opt-in.

### A.8 🟡 Research path silently drops `provider` and `max_results`

**Files:** `search.py` — `web_search()`; `agent_tools.py` — `research()`.

`web_search(query, search_only=False, provider="exa", max_results=10)` accepts both
knobs and forwards **neither**: it calls `self._tb.research(topic=query, depth=depth,
max_tokens=max_tokens)`. So "search with Exa then fetch" quietly becomes "search with
the default chain then fetch", and `max_results` evaporates. The schema advertises
control the implementation doesn't honor — worse than not having the parameter.

**Fix (either):** thread `provider`/`max_results` into `research()` (use them for the
planning search: `search_web(topic, max_results=..., provider=...)`), or remove them
from the `search_only=False` contract and document that research uses the toolbox
default chain. The former is clearly more useful.

### A.9 🔵 Stale `dropped_dupes` after a search-cache hit

**File:** `search.py` — `search_web()` / `_search_failover()`.

`_last_search_dropped` is reset only on the miss path. On a cache hit the method
returns early *without* resetting it, so `research()`'s `dropped_dupes` field reports
the drop count of some earlier, unrelated query. (The code comment even claims the
hit path "reports 0" — it doesn't; it reports whatever the last miss left behind.)

**Fix:** set `self._last_search_dropped = 0` on the cache-hit path.

### A.10 🔵 `check_sources(mode="content")` is a silent no-op variant

`mode` accepts `"content"`, described as *"reserved for a future full-fetch variant"*,
but behaves byte-identically to `"status"`. An agent that passes `"content"` and
reads the summary has no way to know it didn't get what it asked for.

**Fix:** either implement it (fetch headers-only via the existing pipeline) or reject
unknown/non-implemented modes with an explicit `{"error": ..., "mode_requested": ...}`
instead of silently downgrading.

## B. Things that don't (quite) work: inconsistencies between paths that should agree

### B.1 Four URL identities that disagree with each other

There are four independent "same URL?" implementations, and they give different
answers for the same pair:

| Function | `www.` handling | trailing `/` | query string |
|---|---|---|---|
| `config.normalize_url` | keeps | keeps | keeps |
| `agent_tools._cache_key` | **strips** | **strips** | strips tracking params |
| `search._result_url_key` | keeps | strips | **keeps** |
| `dedup._url_key` | keeps (`www.` ≠ bare) | strips | **drops** |

**Reproduced consequences:**

- `batch_inspect_pages(["example.com", "https://example.com/", "https://example.com"])`
  performs **two full fetches** of the same resource: the batch `seen` set uses
  `normalize_url` (`https://example.com` ≠ `https://example.com/`), while the page
  cache key would have collapsed them.
- `dedupe()` does **not** collapse `https://www.Example.com/docs/` vs
  `https://example.com/docs` (**reproduced**: `len(kept) == 2`), while `_cache_key`
  treats them as one entry. So search results can carry www-duplicates that the
  cache then serves twice, and `research()` can fetch the same page under two URLs.
- `_result_url_key` (search failover path) keeps the query string while `dedup._url_key`
  (check_sources path) drops it: `?page=1` vs `?page=2` are different results in one
  tool and the same result in another.

**Fix:** one canonicalizer used by all four call sites (extend `normalize_url` with
explicit flags, or promote `_cache_key`'s canonical form). This is the highest-leverage
consistency fix in the tree — it touches dedup quality, cache hit rate, and crawl
visited-set correctness at once.

### B.2 `research()` has no `provider` — and `search_only=False` pretends it does (see A.8)

Covered above; listed here because it's also the reason `web_search`'s two modes have
different provider semantics with no documentation of the difference.

### B.3 Crawl has no fetch-strategy knob; `research()` has no budget-per-source knob

`Crawler.crawl()` calls `_inspect_html_page_impl(url, None, "", 0, 1, ...)` — hardcoded
`use_smart=None` (→ auto), no way to force `static` for a politeness-sensitive crawl or
`browser` for a JS-heavy site, even though every other fetch surface exposes the
tri-state. Similarly, `research()` fetches each source with the toolbox-global budget;
there is no per-source cap, so one huge source can eat the `_fit_json` shrink budget
and starve later sources before `_shrink_research` even runs (it mitigates, but only
after full pages were fetched, truncated, and serialized).

### B.4 Adapter politeness state is per-call, i.e. effectively stateless

`research_categories._make_adapter()` constructs a **new adapter on every call**, and
`RateLimit` enforcement lives on the instance (`_last_search`, quota counters). The
engine path reuses persistent toolbox providers, so its politeness actually accumulates
across calls; the adapter path (`research_by_category`) gets a fresh `0.0` timestamp
every time. Cross-call throttling and quota accounting for OpenAlex/Crossref/arXiv/…
therefore don't function in the primary entry point. (Within-call retry still works.)

**Fix:** cache adapter instances per provider id on the toolbox (or a module-level
registry with a lock), so rate state persists for the process lifetime.

### B.5 Sitemap probes skip politeness, robots, and (Python-side) SSRF checks

**File:** `discovery.py` — `_probe_sitemaps()`: up to 10 sitemap fetches go out via
`_static_fetch` with **no `_rate_limit_domain` call**, no robots check on the sitemap
URLs themselves, and child URLs taken from sitemap XML are queued without
`_validate_url` (only the first `/sitemap.xml` is validated). The Rust core's SSRF
guard is the backstop, so this is defense-in-depth rather than a hole — but a hostile
or giant sitemap can still trigger 10 rapid same-host fetches, and.redirect chains
from sitemap entries are only validated one layer up.

### B.6 `BatchEntry` provenance gaps: batch `chars_total` is 0, single-read is real

**Reproduced:** the same `https://example.com` read via `batch_inspect_pages` reports
`"chars_total": 0` (and `fetched_at/http_status/final_url/content_type: null`) while
`inspect_html_page` reports the real values. Root cause: `_batch_result` builds the
`InspectionResult` from the truncated slice and never sets the Tier-1.2/1.3 read-time
fields the single path sets (`offset/next_offset/has_more/chars_total` come from
`_inspect_html_page_impl`, provenance via `_apply_provenance` — which *is* called, but
with `page_markdown=md` where `md` is already the truncated slice in the batch path,
so `content_hash` covers the slice, not the full page as documented in M11). Two
reads of the same URL therefore yield different hashes depending on which tool read
first — the M11 "every chunk shares one hash" invariant breaks across the batch seam.

### B.7 `focused_discovery` seed handling vs. search-prior handling is asymmetric

Seeds get full SSRF validation with specific skip reasons (`"ssrf blocked"`,
`"seed below min score"`); search-prior URLs skip validation entirely and land in the
fetch queue, where failures surface as generic fetch `errors` instead of `skipped`
reasons. Both end up safe (fetch-time `_prepare_url` enforces the guard), but the
payload tells two different stories about the same event, and `errors_total` is
inflated by what is really a filtering decision.

### B.8 `extract_document(pages=...)` range-read cache entries lose their bounds

`models.ExtractionResult` documents it honestly (`page_start/page_end` "stay 0/None"
on a range cache hit), but the consequence is real: a cached `pages="10-20"` read
returns `content` with no machine-readable statement of which pages it contains
(`page_range` echoes the request string, unvalidated against clamping). An agent
paginating a PDF from cache cannot distinguish "pages 10–20" from "pages 10–13
because the doc only had 13".

## C. Needs refinement (works, but below the bar the rest of the codebase sets)

### C.1 Unbounded growth in three places the codebase otherwise bounds (M7)

The project carefully bounds `visited_urls`, `_domain_last_seen`, `_search_mem`,
latency windows, and crawl queues — then leaves these unbounded in long-lived MCP
server processes:

- `guard.JailGuardGuard._verdicts`: `sha256(chunk) → verdict`, never evicted. A server
  scanning distinct web content all day grows this forever.
- `models.FetchStats._by_domain` / `_by_error`: one entry per distinct domain/error
  string, forever. A broad crawl (`same_host=False`) is exactly the workload that
  explodes the key space.
- `search_providers` per-adapter `_last_search`-style state is fine (fixed keys), but
  any `RateState` history kept per-host would join this list — audit before adding.

**Fix:** LRU-cap all three (the codebase already has the `OrderedDict` + `popitem(last=False)`
idiom in four places; reuse it), and add a test asserting bounded growth.

### C.2 `research()` still lives on the facade; the composition split is ~85% done

`agent_tools.py` is down from 5100 to ~1200 lines, but `research()` (Tier 3.13
orchestration: plan → validate → fan out → shrink) is still a 130-line facade method
reaching into `self._search`, `self._fetch`, and `self._budget`. It's the last
orchestration concern that hasn't moved to a collaborator, and it's the one most in
need of unit isolation (planning vs. fetching vs. shrinking are currently only
testable through live-fetch mocks). `SearchService.web_search`'s docstring even notes
the delegation runs the wrong way ("delegated back to the toolbox (Crawler) via
`self._tb.research`" — research isn't on the Crawler at all).

### C.3 Keyword classifier has the generic-term problem the thesaurus solved

`research_categories` keyword lists include bare high-frequency tokens: `"bill"`,
`"share"`, `"shares"`, `"index"`, `"indices"`, `"abstract"`, `"court"`, `"market"`,
`"weather"`-adjacent generics. First-keyword-wins ordering means "stock photos of
bill murray" → `financial`, "court yard garden design" → `legal`, "my thesis on
market street" → `scholarly`/`financial` coin flip. The thesaurus module documents
exactly this lesson ("deliberately no ultra-generic tokens") — the classifier predates
it and never got the same treatment.

**Refinements:** multi-word-phrase priority (score `"code of federal regulations"` above
`"bill"`), per-category score-then-argmax instead of first-hit-wins, and a small
confusion-matrix test over adversarial queries. Cheap, high user-visible value: a
misclassified query sends the agent to the wrong data source entirely.

### C.4 Hardcoded operational constants with no config path

- Document fetch: `httpx.Client(timeout=30)` (`document.py`), robots fetch
  (`robots.py`, 5 s), sitemap fetch (inherits static defaults), liveness default 10 s
  (configurable only via `ToolboxConfig.liveness_timeout` — good, but undiscoverable:
  no `GOSSAMER_LIVENESS_TIMEOUT` env var in `mcp_server.py`).
- `Crawler` caps (`_CRAWL_MAX_DEPTH/PAGES/QUEUE_CAP/LIST_CAP/PAGE_CHARS`), guard
  `chunk_chars`, cache `max_memory_entries` (100, not exposed in `ToolboxConfig` at
  all — the constructor takes it, the config doesn't forward it).
- `GOSSAMER_LOG_LEVEL` is read in `main()` but undocumented in the module docstring's
  env-var table (every other var is listed).

**Fix:** audit pass adding the missing `GOSSAMER_*` bindings + `ToolboxConfig` fields;
document `GOSSAMER_LOG_LEVEL`. Operators can't tune what they can't see.

### C.5 `inspect_html_page` paging edge: `offset` past EOF is a silent empty success

`offset > len(markdown)` clamps to EOF and returns `markdown: ""` with
`has_more: false`. Indistinguishable from "page has no content" except via
`chars_total`. A one-line `{"warning": "offset beyond end of content"}` (or clamping
`next_offset` reporting) would save agents a confused round-trip.

### C.6 `fit_context_window` drops content silently; `_truncate` markers vary

`fit_context_window` skips pieces that don't fit with no record of what was dropped
(compare `_shrink_research`, which reports `sources_omitted` — the codebase knows the
right pattern). And three different truncation markers coexist:
`"\n\n... [truncated]"`, `"\n\n... [truncated for token budget]"`, `"..."`.
Unify + report.

### C.7 Ruff rule selection is extremely narrow (`E4,E7,E9,F`)

Only syntax/undefined-name level. The tree would benefit from at least `B` (bugbear:
mutable-default-argument `B006` would have caught **A.5** statically), `I` (import
order — the split modules have growing import blocks), and `UP` (py310+ idioms).
The current pin comment explains *why* the set is pinned; extend the set, keep the pin.

## D. Missing (gaps worth planning, not bugs)

1. **Per-call output budget.** `inspect_html_page` / `batch_inspect_pages` /
   `focused_discovery` all use the toolbox-global `max_tokens`/`max_markdown_chars`.
   An agent doing one big background read and many small foreground reads cannot size
   them independently without constructing two toolboxes (which splits the cache).
2. **Crawl sitemap seeding.** `discover_resources` (sitemap-aware) and
   `focused_discovery` (link-graph) don't talk to each other: the crawl never consults
   `/sitemap.xml` for frontier seeds, and discovery never scores. A `seed_urls`-from-
   sitemap one-liner in the agent docs would cover 80% of this; a `use_sitemap` flag
   would cover the rest.
3. **`llms.txt` awareness.** Same category as above: check `/llms.txt` (and
   `/llms-full.txt`) during discovery; it's increasingly the highest-signal
   machine-readable source on a site.
4. **PDF/Office image extraction.** Documented as unavailable (pdf_oxide detects but
   can't extract image bytes). Figures, charts, and scanned pages are therefore
   invisible — the largest recall gap in document handling. Track upstream or shell to
   `pdfplumber`-style fallback behind the same interface.
5. **Legacy Office formats.** `.doc/.xls/.ppt/.odt/.rtf/.epub` return conversion-hint
   errors by design (M16). A `libreoffice --headless --convert-to` optional path would
   close the most common real-world failure ("the report is a .doc").
6. **No `fetch_mode`/strategy override on crawl, research, or discovery.** All three
   orchestration surfaces hardcode their fetch strategy while both primitive surfaces
   expose the tri-state.
7. **Observability gaps in `get_stats()`.** Search-result cache (size/hits), robots
   cache (hosts/rules), adapter rate-state, crawl counters, and uptime are all missing;
   the `fetches` section is good — extend the pattern rather than inventing a new one.
8. **No request timeout / cancellation plumbing.** Rust fetch has a fixed 30 s timeout;
   batch/crawl loops can't be cancelled mid-run; MCP clients get no progress callbacks.
   A `timeout_s` config + per-call override covers the realistic need.
9. **Structured error taxonomy.** `SPEC_AUDIT.md` already lists this ("no custom
   exception hierarchy"); it still holds for *tool payloads*: `error` vs `warning` vs
   `error_type` conventions differ per tool (`research` uses `status: ok/error` records,
   crawl uses `errors[]` + `skipped[]`, batch uses inline `error` keys). A documented
   envelope convention would let agents branch reliably.
10. **No raw-HTML passthrough.** Debugging extraction quality ("why did this table
    vanish?") currently requires re-fetching outside the tool. A `store_dir`-style
    `save_html` or debug flag on inspect would close the loop using existing plumbing.
11. ** playwright/SPA coverage is single-engine.** Only `browser_oxide` (macOS/Windows
    wheels; no Linux wheels on PyPI — README notes this) with static fallback. Linux
    server deployments effectively have no JS rendering. Document the platform matrix
    explicitly or add a Playwright optional path.
12. **Search-provider breadth.** `research_by_category` covers scholarly/legal/financial/
    geo/general, but several adapters in `research_providers.py` (NASA, NVD, Congress,
    Census, GitHub, OpenLibrary, Zenodo…) aren't reachable through any category —
    they're importable but unwired from the tool surface. Either wire them or document
    them as library-only.

## E. What doesn't work today (verified broken or dead, not just missing)

1. **E.1 — `requirements.txt` fresh-install test path is broken** (see A.7). Not
   "inconvenient": `pytest` exits with an error before collecting anything.
2. **E.2 — `search_only=False` + `provider=` is accepted and ignored** (see A.8).
   Verified live: Exa-requested research ran the DDG chain.
3. **E.3 — Batch reads of the same page disagree with single reads on provenance and
   identity** (see B.6): `chars_total: 0`, null provenance fields, slice-hash vs
   full-hash. Verified live against `example.com`.
4. **E.4 — `GOSSAMER_MAX_TOKENS=notanint` prevents server start** (see A.6). Verified.
5. **E.5 — Live-network suite is effectively unrunnable in CI**: 10/11 skips are
   `GOSSAMER_LIVE`-gated with no recorded run, no VCR/cassette layer, and key-gated
   providers skip silently. There is no way to distinguish "live path works" from
   "live path rots" without a human setting keys. Consider `pytest-recording`-style
   cassettes for the provider adapters at minimum.

## F. Documentation / metadata drift (small, but trust-eroding)

1. **Version triple drift:** `pyproject.toml` = 0.5.7, `Cargo.toml` = 0.5.3,
   `research_providers._UA` = `gossamer/0.5.3`. The UA string also leaks
   a stale version to every adapter request. Derive all three from one source
   (`importlib.metadata` already feeds `__version__`; use it for the UA too).
2. **README tool count:** "Returns OpenAI-compatible function definitions for **all
   seven tools**" (§LLM Tool Definitions) — the registry has **10**. The feature list
   also omits `research_by_category`, `export_citations`, and `check_sources` while
   documenting older tiers in depth.
3. **README test badge:** "1194 passing, 11 skipped" vs. actual **1206 passed**.
   (Nit, but it's the first thing a visitor reads.)
4. **SPEC_AUDIT §8** still says "114 tests passing" and its §2 tool list predates
   `research_by_category`/`export_citations`/`check_sources`. Either re-verify-and-stamp
   or mark superseded — a stale audit is worse than none because it asserts coverage
   that moved.
5. **`__init__.py` exports lag the tool surface.** `WebResearcherToolbox` is the only
   public path to `research_by_category` / `export_citations` / `check_sources` /
   `search_category` / `check_liveness` / `dedupe`. Direct imports work but aren't
   re-exported, so `from gossamer import check_liveness` fails. Decide the
   public surface and export it.
6. **`check_sources` docstring/schema vs. behavior:** schema says "Probe whether source
   URLs are reachable **without downloading** their pages" — true for `status` mode;
   `content` mode (same behavior today) contradicts the sentence it sits next to.
